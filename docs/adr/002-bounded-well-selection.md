# ADR 002 — Explicit bounded well selection and immutable versions

Date: 2026-10-10. Status: implemented for independent acceptance review; actual public-source and browser evidence belongs in the dated verification packet.

The owner authorized the bounded website lookup/selection/collection expansion after the five-validation closure. This changes the old prohibition on trigger controls only for a separate collection panel. Selecting a workflow node still inspects recorded evidence and never executes a stage. RRC-01–06 and RRC-09/10 apply; statewide collection, scheduling, GIS and automatic Analytics import remain outside this decision.

The local server constructs exact official Socrata predicates. UIC is an original nine-digit string and API is the original eight-digit source string. Longer API forms, numeric inputs, unsupported kinds, extra request fields and caller-supplied URLs/paths/query expressions are refused. Leading zeros are retained. Lookup preserves the metadata response, candidate response, retrieval sidecars and query/hash manifest under a server-generated UUID. At most 25 candidates are returned. Exactly 25 means cap reached and blocks selection. Empty results and duplicate UIC parents have distinct presentation.

Selection requires the lookup UUID and explicit source-record key. Collection reloads and validates the preserved evidence; it does not trust a caller-provided public flag. Persisted selection must contain matching lookup ID, raw ordinal, source-record key and lookup hash. The fresh exact-UIC inventory query must return exactly one parent whose original UIC/API/operator/district/lease/well/W-14 identity matches the chosen row. This catches duplicate UIC parents absent from an API-specific lookup and identity changes between requests.

Query contract v2 covers one UIC and 1–36 inclusive reporting months. December rolls into January correctly. The official monthly query uses a lower inclusive timestamp and an upper exclusive timestamp. A 1,000-row response blocks publication because completeness is unproven. All retained rows are checked against exact UIC and reporting-window predicates. Scope contradictions retain their raw rows and quarantine accounting in failed run evidence; they cannot produce a verified artifact. Successful empty monthly responses remain explicitly incomplete history, rather than zero injection.

`collectPublicSnapshot`, `loadSnapshot`, normalization, `buildArtifact` and `exportArtifact` carry the same versioned scope. V2 artifacts use transformation `rrc-odp-v2.0.0`, retain compatible CSV columns and the typed JSON wrapper, and include the acquisition marker, selection, lookup raw/metadata bytes and all retrieval sidecars under `sources/`. These evidence files are hashed in the manifest, so exporting from the artifact's own `sources/` independently reproduces the same version. V1 replay retains its exact legacy query, fourteen-file source-proof exception and original artifact bytes; the exception is not broadened.

Fixture classification is inspected across all available acquisition/lookup/retrieval markers before validation failures can occur. A contradictory caller mode, failed or malformed marker, missing source, invalid scope or selection error cannot turn retained fixture evidence into public history. Fixture invocations never enter actual run history or available public dataset versions. New source evidence must satisfy the recorded acquisition contract; URL shape is insufficient.

The server adds POST `/api/lookup` and POST `/api/collect`; GET/HEAD `/api/versions` exposes available publication pins. GET/HEAD `/api/versions/<artifact-id>/download` downloads a deterministic TAR of the whole available public version. It verifies the saved manifest/normalized pins, every contract/source evidence hash and byte count, and publication pins against recorded export evidence. It rejects fixture versions, unavailable IDs, traversal/linked paths, oversized files and changed evidence; total archive source bytes are capped at 80 MB, individual files at 10 MB. Writes require an exact same-origin HTTP loopback Host/port and loopback connection. JSON requests are bounded to 8,192 bytes. One lookup and one collection may run at a time. Identifiers/directories/version IDs are generated by the server. Failures return structured, redacted errors and the actual three-stage record where available; partial sources and failed runs are retained. History persistence failure rejects the invocation even if publication completed.

Publication writes `version-pins.json` once alongside the new immutable version. The version registry reads those saved pins only when their hash matches the validated successful public run's export evidence. It does not hash current mutable artifact bytes to manufacture new pins. The browser verifies manifest and normalized-file bytes against the chosen publication pins before replacing records, details, sources and downloads. Tampering therefore fails closed. Run selection is independent of dataset selection; neither changes the original default pins or an Analytics pin. Slower lookup and version responses cannot overwrite a newer identifier or selection.

Candidate displays retain original identity, available permit/source fields, API county-prefix basis and retrieval evidence. County names outside the established Reeves mapping are not invented. Permit limits remain regulatory constraints. Source rows, quality dispositions, dictionary, hashes and the complete selected version's evidence remain available for handoff independently of table filters. A successful export never supplies consumer acknowledgement or complete-project acceptance.

The original CLI acquisition syntax continues to collect its documented legacy scope. A v2 snapshot created by the local website can be replayed with `node scripts/export.mjs --source-dir <snapshot-directory> --artifact-id <existing-version-id>`. Choose a new version ID for a changed snapshot; conflicts and incomplete existing versions are refused.

Validation: new query/date, lookup/selection, collection/replay, fixture-failure, local API and selected-version tests plus unchanged legacy tests run in an isolated repository copy. Test response fixtures remain explicitly labeled; they establish implementation behavior, not public acquisition. Independent adversarial tests cover the reviewed failure paths. Live source anchors, actual website/mobile/keyboard/download checks and final independent review remain Main-owned acceptance evidence.
